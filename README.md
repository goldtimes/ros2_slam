# 定位建图算法
重构的一版本定位建图算法，目前支持lidar/imu/encoder/gnss等传感器，未来会支持相机传感器.
该算法的核心是ieskf算法，为什么采用ieskf算法，因为目前对它的理论和代码编写比较熟悉。基于优化的方式代码会比较困难

## 编译中的优化
```
1. 调试与优化基础选项
-g
生成调试信息（保留符号表和调试符号），便于使用 gdb 等调试工具调试程序。
注意：虽然与 -O3（最高级优化）同时使用可能导致调试体验下降（优化会改变代码结构），但该组合在需要 "带调试信息的优化版本" 时常用（如定位性能相关的 bug）。
-O3
开启最高级别的编译优化（第三级），包含 -O2 的所有优化，并增加更激进的优化（如循环展开、函数内联、寄存器优化等），显著提升程序运行速度，但会增加编译时间和二进制体积。
编译时间变长： -O3 优化会增加编译器的计算量，导致编译时间显著延长（尤其对大型项目）。
二进制文件变大：由于更多的代码展开和优化，生成的可执行文件或库可能比 -O0（无优化）或 -O2 更大。
调试难度增加：优化后的代码可能会改变变量的生命周期、指令顺序等，导致调试时变量值显示异常或断点位置不准确（建议调试时使用 -O0）。
兼容性风险：极少数情况下，过度优化可能导致代码行为异常（如依赖未定义行为的代码），需要结合测试验证。
2. 浮点与数学优化选项
-fsee（应为 -ffast-math 的笔误，或特定编译器扩展）
若为 -ffast-math：启用快速数学优化，牺牲部分 IEEE 浮点标准兼容性（如不检查 NaN/Inf、允许重新排序浮点运算），以换取更快的浮点计算速度。
若确实是 -fsee：可能是特定平台 / 编译器的选项（如某些嵌入式编译器），通常与 SIMD 指令优化相关。
-fomit-frame-pointer
禁用栈帧指针（frame pointer），减少函数调用时的寄存器开销，释放更多通用寄存器用于计算，提升执行效率。
副作用：可能导致栈回溯（如崩溃时打印调用栈）变得困难，调试时定位问题稍复杂。
-fno-signed-zeros
告知编译器假设浮点运算中不会出现 “带符号的零”（+0.0 和 -0.0），允许编译器对涉及零的浮点运算进行优化（如简化表达式），适用于不依赖带符号零语义的场景。
-fno-math-errno
禁用数学函数（如 sin、sqrt）设置 errno 错误码的行为，减少函数调用的额外开销（无需检查和设置错误码），加快数学运算速度。
注意：若程序依赖 errno 判断数学函数错误（如定义域错误），则不应使用此选项。
3. 循环与代码结构优化
-funroll-loops
开启循环展开优化，将循环体重复多次以减少循环控制语句（如 for 循环的条件判断、计数器自增）的执行次数，提升循环执行效率。
对迭代次数固定且较小的循环效果明显，编译器会自动判断是否展开。
```

# 回环检测的功能
回环检测的功能主要是为了提高定位的准确性和稳定性，尤其是在长时间运行或大范围环境中。通过检测到回环，可以进行地图优化和误差校正，从而提升整体的SLAM性能。
## 回环检测的设计
1. 主线程
  - 从里程计中获取里程计数据,将里程计数据转换为位姿变换（PoseTrans),然后转换为Pose3
  - 接受配准后的点云信息
  - 根据里程计判断是否为关键帧
  - 如果是关键帧，保存关键帧和关键帧位姿，并给予id
  - 构建因子图，第一帧为初始帧，其他帧为关键帧，每个关键帧之间有位姿约束
2. 回环检测线程
  - 基于距离的回环检测/或基于描述子的回环检测
  - 如果检测到回环，构建回环约束，并加入因子图中
3. 回环确认线程
  - 通过点云配准，判断回环是否正确
  - 如果回环正确，更新因子图
  - 找到回环约束的两个关键帧，更新它们的位姿约束
